## How I approach problems

1. **Understand the workflow.** Who uses the system, what decision do they need to make, and where does the process break?
2. **Build an end-to-end solution.** Model the data, expose useful APIs, design the interface, and integrate the tools already in use.
3. **Make the system dependable.** Think about access control, failure cases, migrations, tests and operational visibility.
4. **Explain the trade-offs.** Document why the design works, where its limits are, and what should come next.
